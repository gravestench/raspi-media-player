# Structured logging

The service uses Go's `log/slog` package. Daemon deployments default to one JSON
object per line; local development defaults to readable text. Configure these
with `RASPI_MEDIA_PLAYER_LOG_FORMAT` (`json` or `text`) and
`RASPI_MEDIA_PLAYER_LOG_LEVEL` (`debug`, `info`, `warn`, or `error`).

Every completed HTTP request includes:

- `request_id`: generated by the server or accepted from `X-Request-ID`
- `method`, `path`, and the matched `route` pattern
- `status`, `duration_ms`, and `response_bytes`
- `remote_address`

Request-scoped events use the same request ID. Lifecycle events include service
startup, shutdown requests, clean shutdown, and fatal startup failures.

Keys that indicate passwords, credentials, authorization, cookies, sessions,
tokens, or secrets are replaced with `[REDACTED]` by the logging handler. Do not
place sensitive values in log messages or non-sensitive field names.

The init.d deployment writes JSON logs to
`/var/log/raspi-media-player.log`. For example:

```json
{"level":"INFO","msg":"http request","request_id":"abc123","method":"GET","path":"/api/v1/health/ready","route":"GET /api/v1/health/ready","status":200,"duration_ms":0,"response_bytes":19,"remote_address":"192.168.1.10:50123"}
```
